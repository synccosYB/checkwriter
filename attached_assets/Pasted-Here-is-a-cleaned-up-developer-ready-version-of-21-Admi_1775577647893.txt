#21 - Admin Frontend Dashboard — Full Control UI

## Objective

Build the frontend admin dashboard pages that consume the new admin backend APIs and give superadmins a complete control panel for managing and reviewing the full system.

This task expands the current admin area from basic user/mail management into a full platform administration UI.

---

## What & Why

The current admin dashboard is too limited for real system operations. Superadmins need a frontend interface to manage users, review records across all accounts, inspect audits, update platform settings, review integrations, and investigate imports and attachments.

The backend task adds the APIs. This frontend task must expose that functionality in a clean, structured, admin-only dashboard using the existing MUI-based patterns already used in the app.

The result should feel like one consistent admin control center, not a collection of disconnected screens.

---

## Done looks like

### Navigation

A new expanded **Admin** section appears in the sidebar with links to all admin pages.

### User management

The existing User Management page is enhanced to support:

* activate / deactivate user accounts
* manual custom subscription price overrides
* improved filtering and search

### Global entity management

Superadmins can use dedicated pages to view and manage:

* all checks across all users
* all bank accounts across all users
* all payees across all users
* all organizations
* all transactions across all users (read-only)

### Observability

Superadmins can view:

* audit logs with filtering
* integration statuses across QuickBooks / Stripe / Plaid
* all attachments
* all check import history

### Configuration

Superadmins can manage:

* platform settings
* mailing prices through a dedicated settings section

### Security

All pages are protected by the existing `AdminRoute` guard.

### Design consistency

All screens use the same MUI-based UI patterns, spacing, table behavior, dialogs, cards, and filter interactions already present in the app.

---

## Out of scope

* Backend API work
* Mobile-specific layouts
* CSV / Excel / export functionality
* Real-time live refresh or websockets
* Redesigning the entire admin dashboard visual language
* Replacing existing MUI-based patterns with another component approach

---

## Core implementation principles

### 1) Follow existing admin UI patterns

Do not invent a second design system for these pages. Reuse existing admin table layouts, dialogs, filter bars, page headers, and action menus wherever possible.

### 2) Admin pages should feel cohesive

All pages should share common patterns for:

* page titles
* table toolbars
* search/filter sections
* pagination
* row actions
* dialogs / edit modals
* loading / empty / error states

### 3) Prefer reusable components over one-off page code

Where multiple admin pages use the same behavior, create reusable building blocks.

Examples:

* reusable admin data table wrapper
* reusable filter bar
* reusable confirmation dialog
* reusable status badge
* reusable edit modal patterns
* reusable detail drawer or expandable row patterns where needed

### 4) Respect backend permissions and route protection

Frontend route guards are required, but backend authorization remains the source of truth.

### Goal

Extend the current User Management page rather than replacing it.

### Additions

* activate / deactivate action per user
* custom subscription price action
* better filtering and search controls
* clearer status display for active vs inactive users
* optional display of price override if present

### UI behavior

Each user row should support actions such as:

* edit existing user behavior if already present
* activate / deactivate
* set custom price

### Suggested UI elements

* status chip for `Active` / `Inactive`
* action menu or inline action buttons
* modal for custom subscription price editing
* filter controls for:

  * active status

  * maybe subscription override presence if useful

### Acceptance

* Admin can activate and deactivate a user from the page
* Admin can open a modal to set or clear a custom subscription price

### Errors

Show user-friendly admin errors, especially for:

* failed saves
